# 3D 物料转运投影

状态：Accepted（前端只读投影）
日期：2026-08-05
适用范围：`uni-lab-fe` 的工作流（Workflow）、物料（Material）与 Pascal 3D 集成

## 目标

在现有 Pascal 原生场景中增加一个可关闭的物料转运投影层，用于回答：

- 物料（Material）计划从哪个库位（Site）前往哪个库位（Site）；
- 哪个执行器（Executor）负责转运；
- 当前转运处于计划、运行、成功或异常中的哪一状态；
- 工作流（Workflow）画布当前选择的转运节点在 3D 中对应哪条路线。

该能力不创建第二份场景，也不引入新的物料位置权威。

## 权威与身份

| 信息 | 权威来源 | 前端用途 |
| --- | --- | --- |
| 库位（Site）及空间姿态 | 物料图（Material Graph）的 `MaterialAggregate.sites` | 计算路径端点和蓝色空间锚点 |
| 计划转运关系 | 已发布复合工作流节点的 `workflow_source` 身份及参数 | 生成源到目标的只读路径 |
| 执行状态 | 工作流节点作业（WorkflowNodeJob） | 为路径选择计划、运行、成功或异常样式 |
| 当前物料位置 | 物料图（Material Graph）的 `placement` | 渲染真实物料位置；不随前端动画改写 |

工作流节点只有在其已发布来源身份被识别为标准物料转运工作流，且同时提供
`source_warehouse`、`source_site`、`target_warehouse`、`target_site` 与
`target_device` 时，才会生成路线。节点名称和 UISchema 文案不是语义依据，
物料来源（MaterialSource）也不会被误判为物理转运。

前端材料适配层把后端物料图 `material.meta_data.source_node_id` 保留为内部
`config.sourceIdentity`，用于把工作流参数中的逻辑资源引用解析到具体物料
（Material）UUID。该字段只作为后端已给出的稳定别名，不从名称或显示文案推断。
若工作流引用的仓库尚未出现在物料图中，对应路线保持未解析并拒绝渲染。

跨面板交互只传递稳定身份：当前工作流 UUID、当前工作流任务 UUID 与选中的
工作流节点 UUID。完整工作流文档、工作流任务（WorkflowTask）和 Pascal 场景
对象不进入共享交互 Store。

## 生命周期与失败语义

1. 选择工作流（Workflow）后，3D 集成读取当前已应用编写图。
2. 读取该工作流最新的工作流任务（WorkflowTask）及工作流节点作业
   （WorkflowNodeJob），并订阅运行态失效通知。
3. 纯投影器从已发布复合工作流节点生成路线，再按子节点作业聚合状态。
4. Pascal 适配层使用物料图（Material Graph）解析源、目标库位（Site）的世界
   坐标；任一端点无法解析时，该路线拒绝渲染，并在图层摘要中计入未解析项。
5. 运行态刷新失败时保留最后一次一致投影并显示降级提示，不伪造成功状态。

状态聚合优先级为：需要关注或执行未知、失败或超时、运行或已派发、取消、全部
成功、等待执行。只有运行中的路径播放方向动画；系统启用减少动态效果时，路径
保持静态方向标记。

## 交互和视觉

- 蓝色圆点表示可定位的库位（Site）空间锚点，不表示“运行中”。
- 机械臂图标表示执行器（Executor），不是可直接下发命令的按钮。
- 运行使用橙色，成功使用绿色，异常使用红色；蓝色保留给空间定位与选择。
- 路径端点和执行器标识使用短标签与悬浮说明，避免遮挡设备模型。
- “物料转运”图层开关与“库位和点位”开关并列，并分别持久化。

## 明确非目标

- 不从 3D 直接调用设备动作或工作流控制接口。
- 不根据路径动画提交 `move`、`attach`、`detach` 或
  `host_node.transfer_resource`。
- 不把插值中的临时坐标写回物料图（Material Graph）。
- 不用前端字符串猜测任意动作是否产生物理转运。
- 本轮不修改 Uni-Lab-OS；若未来需要跨执行器的实时轨迹点，应先定义新的
  操作系统（OS）读协议，再扩展本投影层。
